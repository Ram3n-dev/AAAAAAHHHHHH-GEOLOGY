# Критерии приёмки

Задача принимается, когда все её критерии проверены не автором и отмечены.
Формат: «Дано — Когда — Тогда». 

## 1. Критерии приёмки PoC

- [ ] **П-1.** Проект разворачивается одной командой (`docker compose up`) из репозитория на чистом компьютере; интерфейс открывается в браузере.
- [ ] **П-2.** Таблица признаков пересобирается скриптом из сырых данных: удалили результат, запустили скрипт — получили таблицу с тем же числом строк и столбцов.
- [ ] **П-3.** Есть карта перспективности на всю площадь (58.5–60.6° с. ш., 92.3–95.0° в. д.) без пустых ячеек.
- [ ] **П-4.** Качество измерено блочной пространственной кросс-валидацией и сравнено с базовым алгоритмом и случайным ранжированием. В топ-10% площади попадает не менее 4 из 11 известных объектов (при случайном ранжировании — в среднем 1).
- [ ] **П-5.** В отчёте есть раздел о смещении изученности: проверено, не выучила ли модель близость к дорогам и посёлкам вместо геологии.
- [ ] **П-6.** По клику на ячейку видна оценка и вклад признаков (см. ФТ-4, ФТ-5).
- [ ] **П-7.** В репозитории есть журнал решений и пояснительная записка: постановка, данные, метод, результаты, ограничения, план на MVP.

## 2. Функциональные требования

### ФТ-1. Карта площади с подложкой
Дано: пользователь открыл приложение.
Тогда: отображается карта, центрированная на площади, с подложкой и контуром границ площади; карта масштабируется колесом мыши и перемещается перетаскиванием.
- [ ] выполнено

### ФТ-2. Включение и выключение слоёв
Дано: открыта карта.
Когда: пользователь отмечает слой в списке слоёв.
Тогда: слой появляется на карте с легендой не дольше чем за 2 секунды; при снятии отметки слой исчезает.
Проверить для каждого слоя: магнитное поле, гравитационное поле, рельеф, известные месторождения.
- [ ] выполнено

### ФТ-3. Карта перспективности
Дано: открыта карта.
Когда: пользователь включает карту перспективности.
Тогда: отображается растр с цветовой шкалой и легендой «низкая — высокая перспективность»; растр совпадает с границами площади.
- [ ] выполнено

### ФТ-4. Оценка ячейки
Дано: включена карта перспективности.
Когда: пользователь кликает по ячейке внутри площади.
Тогда: появляется панель с координатами ячейки и оценкой перспективности (число от 0 до 1).
Когда: пользователь кликает за пределами площади.
Тогда: появляется сообщение «Нет данных для этой точки», приложение продолжает работать.
- [ ] выполнено

### ФТ-5. Вклад признаков
Дано: открыта панель оценки ячейки (ФТ-4).
Тогда: в панели перечислены все признаки с их вкладом в оценку, отсортированные по величине вклада; положительный и отрицательный вклад различаются цветом.
- [ ] выполнено

### ФТ-6. Известные месторождения
Дано: открыта карта.
Когда: пользователь включает слой месторождений.
Тогда: на карте отображаются 11 точек (data/deposits.csv: coord_status=ok, in_aoi=yes); при наведении показывается название объекта.
- [ ] выполнено

### ФТ-7. Переключение метода (желательно)
Дано: включена карта перспективности.
Когда: пользователь переключает «Базовый алгоритм / Модель».
Тогда: карта перерисовывается выбранным методом; оценка и вклад признаков по клику показываются для выбранного метода.
- [ ] выполнено

### ФТ-8. Ранжирование всех ячеек
Дано: рассчитана карта перспективности.
Тогда: оценка есть у каждой ячейки площади, без ограничения количества; ячейки можно упорядочить по оценке (в PoC — проверка по растру оценок; список зон в интерфейсе — в MVP).
- [ ] выполнено

## 3. Нефункциональные требования

### НФТ-1. Развёртывание
Критерий: совпадает с П-1.
- [ ] выполнено

### НФТ-2. Воспроизводимость данных
Критерий: совпадает с П-2; в README описано, какие сырые файлы скачать и какой скрипт запустить.
- [ ] выполнено

### НФТ-3. Единая проекция и сетка
Критерий: все растры площади имеют проекцию EPSG:32646, ячейку 1 км, одинаковые границы и число пикселей (проверка: gdalinfo по каждому файлу).
- [ ] выполнено

### НФТ-4. Скорость
Критерий: при трёх одновременно включённых слоях переключение любого слоя занимает не больше 2 секунд (ноутбук члена команды, браузер Chrome).
- [ ] выполнено

### НФТ-5. Единая UI-библиотека
Критерий: во фронтенде используется одна библиотека UI-компонентов; собственных стилизованных компонентов нет, кроме карты.
- [ ] выполнено

### НФТ-6. Проверка качества
Критерий: в ноутбуке с экспериментами разбиение на обучение и тест сделано блоками территории, а не случайно; размер блока указан и обоснован.
- [ ] выполнено

### НФТ-7. Публичность данных
Критерий: в открытом репозитории нет данных заказчика; все слои PoC — из открытых источников, перечисленных в README.
- [ ] выполнено
