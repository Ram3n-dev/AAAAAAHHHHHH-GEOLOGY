# Требования к прототипу (PoC)

Источник каждого требования указан в скобках. «Бриф» — требование заказчика; «Г1…Г5» — допущение из assumptions.md.

## Пользователь

Главный геолог поисковой партии. Работает с картами и ГИС, не программист. Должен понимать, откуда взялась оценка, и иметь возможность с ней не согласиться.

## Сценарии использования

**С-1. Обзор территории.** Геолог открывает систему, видит карту площади и включает нужные слои данных.

**С-2. Поиск перспективных зон.** Геолог включает карту перспективности и видит, где оценка выше.

**С-3. Разбор оценки.** Геолог кликает по ячейке, видит оценку и вклад каждого признака и решает, согласен ли он с ней.

**С-4. Проверка на известных объектах.** Геолог включает слой известных месторождений и смотрит, попадают ли они в зоны высокой оценки.

**С-5. Сравнение методов.** Геолог переключается между оценкой базового алгоритма и модели и видит, где они расходятся.

## Функциональные требования

- **ФТ-1.** Система отображает карту тестовой площади с подложкой. (бриф) → С-1
- **ФТ-2.** Пользователь включает и выключает слои данных: геофизика, рельеф, геология, известные объекты. (бриф) → С-1
- **ФТ-3.** Система отображает карту перспективности как растр с легендой. (бриф) → С-2
- **ФТ-4.** По клику на ячейку система показывает оценку перспективности. (бриф) → С-3
- **ФТ-5.** По клику на ячейку система показывает вклад каждого признака в оценку. (бриф, Г4) → С-3
- **ФТ-6.** Известные месторождения отображаются точками поверх карты. (Г2) → С-4
- **ФТ-7.** Пользователь переключается между оценкой базового алгоритма и модели. (бриф) → С-5

## Нефункциональные требования

- **НФТ-1.** Проект разворачивается одной командой (Docker Compose). (бриф)
- **НФТ-2.** Таблица признаков воспроизводится скриптом из сырых данных. (бриф)
- **НФТ-3.** Все слои приведены к одной проекции и сетке: UTM 46N (EPSG:32646), ячейка [уточнить: 500 м или 1 км]. (бриф, Г1)
- **НФТ-4.** Переключение слоя на карте занимает не более 2 секунд. (бриф — «карта не должна тормозить», порог — наше допущение)
- **НФТ-5.** Интерфейс собран из одной готовой UI-библиотеки. (бриф)
- **НФТ-6.** Качество измеряется блочной пространственной кросс-валидацией. (бриф)

## Критерии приёмки PoC

- [ ] Проект разворачивается одной командой
- [ ] Таблица признаков воспроизводится скриптом
- [ ] Есть карта перспективности
- [ ] Качество измерено блочной кросс-валидацией и сравнено с базовым алгоритмом и случайным ранжированием
- [ ] Смещение изученности разобрано в отчёте
- [ ] По клику видна оценка и вклад признаков
- [ ] Есть журнал решений и пояснительная записка

## Вне PoC (перенесено в MVP)

Загрузка своих данных, сценарный анализ (изменение весов), работа с полигонами участков, экспорт в GeoTIFF/GeoJSON, авторизация и несколько пользователей.
