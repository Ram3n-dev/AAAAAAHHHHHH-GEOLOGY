# Требования к прототипу (PoC)

«Г1…Г5» — допущение из assumptions.md.

## Пользователь

Главный геолог поисковой партии. Работает с картами и ГИС. Должен понимать, откуда взялась оценка, и иметь возможность с ней не согласиться.

## Варианты использования

См. [usecase.md](usecase.md) и диаграмму [м.png](usecase.png).

## Функциональные требования

- **ФТ-1.** Система отображает карту тестовой площади с подложкой. → ВИ-1
- **ФТ-2.** Пользователь включает и выключает слои данных: геофизика, рельеф, геология, известные объекты. → ВИ-2
- **ФТ-3.** Система отображает карту перспективности как растр с легендой. → ВИ-3
- **ФТ-4.** По клику на ячейку система показывает оценку перспективности. → ВИ-4
- **ФТ-5.** По клику на ячейку система показывает вклад каждого признака в оценку. → ВИ-5
- **ФТ-6.** Известные месторождения отображаются точками поверх карты. → ВИ-6
- **ФТ-7.** Пользователь переключается между оценкой базового алгоритма и модели (желательно). → ВИ-7
- **ФТ-8.** Система ранжирует все ячейки площади по перспективности без ограничения количества. (НР, вопрос 7) → ВИ-3
## Нефункциональные требования

- **НФТ-1.** Проект разворачивается одной командой (Docker Compose).
- **НФТ-2.** Таблица признаков воспроизводится скриптом из сырых данных.
- **НФТ-3.** Все слои приведены к одной проекции и сетке: UTM 46N (EPSG:32646), ячейка 1 км.
- **НФТ-4.** Переключение слоя на карте занимает не более 2 секунд. (бриф — «карта не должна тормозить», порог — наше допущение)
- **НФТ-5.** Интерфейс собран из одной готовой UI-библиотеки. 
- **НФТ-6.** Качество измеряется блочной пространственной кросс-валидацией.
- **НФТ-7.** В публичном репозитории используются только открытые данные с указанными источниками и условиями использования. Данные заказчика с ограничениями доступа не публикуются.

## Вне PoC (перенесено в MVP)

Загрузка своих данных, сценарный анализ (изменение весов), работа с полигонами участков, экспорт в GeoTIFF/GeoJSON, авторизация и несколько пользователей.
